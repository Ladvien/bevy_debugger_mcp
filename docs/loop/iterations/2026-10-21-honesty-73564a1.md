# 2026-10-21 honesty: the tools stopped answering with something else

Focus: honesty · Commits: e93da67..73564a1 · Outcome: fixes only (no release)

## Summary

Five bugs, all of the same kind: a tool answered with something other than what was asked.
`experiment`, `hypothesis`, `detect_anomaly` and `stress_test` each advertised a schema no
handler read, while every handler dispatched on an `action` the tools never sent, so the
caller's request was dropped and a default ran instead. `hypothesis` measured five constants
rather than anything. `replay` recorded nothing. The instructions told agents to use tools
without saying how to call them. Five bugs fixed, each with a check that failed before and
passes after.

The one change from Phase 2 is the tool contract: each tool's request struct now carries the
fields its handler reads, and the handler's own types derive `JsonSchema`, so the advertised
schema is generated from the same type the handler parses.

## Bugs fixed

### B-001..B-004: the four tools dropped the operation they were asked for

Must-fix: misleads y, blocks n, common/no workaround y — `src/mcp_tools.rs:453-517` sent
`type`/`params`/`duration`; the handlers read `action`/`actions`.

Fix: each request struct now carries the fields its handler reads, and the wrapper passes them
through. The handler's own types (`Action`, `Assertion`, `Predicate`, `PerformanceMetric`,
`VariationStrategy`, `StressTestType`, `IntensityLevel`, `ComplexityLevel`) derive
`JsonSchema`, so the schema an agent reads is generated from the shape the handler parses.
`min_severity` was a number to the handler and a string in the schema — the same bug in a
smaller place.

Failing-first check: `tests/tool_contract.rs` (5 tests) — before 0 passed, 4 failed; after 5.

What an agent got, before:

| called | got |
|---|---|
| `stress_test` `type: memory_pressure` | the `spawn_many` test |
| `detect_anomaly` `type: performance` | the default detection |
| `hypothesis` `hypothesis: "the cube keeps moving"` | `Missing 'description' parameter` |
| `experiment` `type: history` | `execute` |

### B-005: hypothesis measured constants

Must-fix: misleads y — `src/hypothesis_system.rs:289-300` returned 16.67 ms, 100 entities,
500 components, 1024 MB, 50% CPU for every metric.

Fix: the two metrics BRP can report — entity count and component count — are measured from
`world.query`. The other three have no way to be observed over the protocol, so they are refused
with a reason that says so and offers the alternative.

Failing-first check: `tests/hypothesis_metrics.rs` (4 tests) — before 0 passed, 4 failed, with
the fabricated numbers in the output (`left: 100.0, right: 2.0`; `left: 500.0, right: 3.0`);
after 4.

### B-006: replay recorded nothing

Must-fix: misleads y — `src/recording_system.rs:328-350` returned an empty map with a `TODO`.

Fix: entity states are recorded from `world.query`. Events are not observable over BRP, so a
frame carries `events_not_captured` and the tool's report names what it captures and what it
does not — an empty event list must not read as "nothing happened".

Two more bugs surfaced while proving this, both in the recording path: the first frame was
dropped (`start_recording` set `last_frame_time` to now, so the first `record_frame` skipped
itself as "too soon"), and the first frame was stored twice (once as the first full frame and
again because `frame_counter % 30 == 0`).

Failing-first check: `tests/replay_recording.rs` (3 tests) — before 0 passed, 3 failed; after 3.

### B-007: the instructions did not say how to call the tools

Must-fix: misleads y — `src/mcp_tools.rs:369-370` pointed agents at `hypothesis`/`experiment`/
`stress_test`/`replay` without naming a single field.

Fix: the instructions now name the fields each tool needs, say that the `action` picks what to
do, and stop claiming that `replay` re-runs the game.

Failing-first check: `tests/instructions.rs` (3 tests) — before 1 passed, 2 failed; after 3.

### B-008, B-014, B-015: the docs said things the code does not do

Must-fix: misleads y (CLAUDE.md, lib.rs) and blocks y (the README, the book).

Fix: CLAUDE.md's capture claim now says what the code does — the fallback is to window
capture, which is weaker than offscreen but not a focus-stealing path. The README and the
book no longer tell the reader to hand-register `bevy_debugger/screenshot`, which double-adds
`RemotePlugin` and panics the game on start; the book was also rewritten around the two capture
sources the plugin has. `src/lib.rs` no longer pins Bevy 0.12.

Failing-first check: `tests/docs_drift.rs` (6 tests) — before 5 passed, 1 failed; after 6.

## Change: the tool contract

Plan: make each tool's request struct the source of truth for both the advertised schema and
the handler's input. Files: `src/mcp_tools.rs`, `src/experiment_system.rs`,
`src/hypothesis_system.rs`, `src/stress_test_system.rs`, `Cargo.toml`. Goal: a tool cannot
advertise a field it ignores, and cannot read a field it did not advertise. Proof:
`tests/tool_contract.rs`, 5 tests.

Candidates considered:
- **The tool contract** (chosen) — the four tools misrouted every request. Evidence: the audit
  in this report; the contract test. Effect: the four tools now do what they are asked. Risk:
  the advertised schemas change, so an agent that had learned the old field names has to learn
  the new ones. The old names advertised nothing the handlers read, so nothing that worked
  stops working.
- **Add an `input` tool** (B-010) — the plugin's input injection is the core capability and
  the server does not expose it as a tool. Evidence: the tool list. Effect: a large new
  capability. Risk: high; it needs the fixture game and the ground-truth harness to be worth
  anything, and neither exists yet. Deferred to a later iteration, once the fixture is there.
- **Delete the `observability` feature** (B-019) — it does not compile, and nothing reachable
  uses it. Evidence: 42 errors, and `src/main.rs` is the only file outside the module that
  mentions it. Effect: the `--all-features` build goes green. Risk: the feature may be
  wanted later, and deleting it is a decision about intent, not about a bug. Deferred: it
  ranks after the honesty bugs, and this iteration had enough.

### The ratchet caught the iteration's own changes

This is worth stating plainly, because it is the check doing its job. The first three gate runs
failed, each on something this iteration had introduced:

1. `result_large_err` 937 → 939. The two new functions in `hypothesis_system.rs` returned the
   crate's `Error` by value, and `Error` carries `reqwest::Error`, which is large. Fixed by
   boxing: `BoxedResult<T, E = Box<Error>>` in `src/error.rs`.
2. `dead_code` 72 → 80. Four `default_*` functions were left behind when the old hand-written
   schemas were replaced by the handler types' own. Removed.
3. `src/lib.rs - (line 30) - compile` failed, then became a *new ignored test*. The quick-start
   example was a `rust,no_run` doctest, so cargo compiled it — and it belongs to the *game*
   crate, using `bevy` and `bevy_debugger_bevy`, neither of which this crate depends on by
   default. It is now a `text` block, and says why. `ignore` was not the answer: it turns a
   broken doctest into a new ignored test, which the ratchet also rejects.

After the fixes: `result_large_err` 935 (baseline 937), `dead_code` 72 (baseline 72), 1460 total
(default level, down from 1462), no lint above baseline, and every touched file at or below its
own baseline count.

## Review

No independent review subagent was run. The reason is in the report rather than hidden: the
iteration ran out of host capacity. The host was running a 17-process C++ build and a vLLM
process for most of the iteration, swap was exhausted, and two test runs were killed by
`systemd-oomd` and one by a bus error. The deterministic gate and the failing-first proofs ran
to completion; the independent review did not. A later iteration should run it.

The skeptic pass was run by hand on the reviewer-facing claims instead: every "before" number
in this report came from a run against the pre-fix code, in a separate worktree for the metrics
bug and by reverting the file for the others.

The ratchet was itself a reviewer that did not go unused: it rejected this iteration's own
commits three times, on three separate regressions, all of which are listed above. That is the
closest thing to an independent check that ran here.

## Next focus

Build the fixture game (`examples/fixture_game`) with known entity counts, a known frame cap,
a UI button and a pickable object at known positions, and one planted bug. It is what the
