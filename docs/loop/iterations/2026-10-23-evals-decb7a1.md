# 2026-10-23 evals: an agent eval suite, and five tools-or-release fixes it was built alongside

Focus: (none; bootstrapping rule: no eval suite) · Commits: 78628fb..71adcb4 (plus the loop-state commit) · Outcome: shipped, released as v0.2.0

## Summary
The loop now has an agent eval suite: 6 dev and 3 held-out debugging tasks against the fixture game,
each run by a fresh headless `omp` session that can reach only this server. Phase 1 fixed four tool
bugs — `stress_test` reported random numbers and success while every operation failed (removed),
`tools/list` reshuffled itself every launch, a missing `bevy_fairy/*` method named no fix (or a
feature that does not exist), and refusals came back with `isError: false` — and one release bug:
`release.yml` published with no token and verified against the local manifest. The human directed that
every iteration push and publish; the loop command says so now, and this is the first iteration run
that way.

## Bugs fixed
### B-034: `stress_test` answered `success: true` while every operation failed, with random frame times
Must-fix: misleads y, blocks n, common/no workaround n — `src/server/stress_test_system.rs:784-797` pushed `16.67 + rand*10` into `frame_times_ms`; spawns used `Transform`, `Health`, `Component_0`; `duration: 1.0` ran 30.12 s against the fixture.
Fix: removed from `tools/list` (the loop's rule for a tool that cannot be made honest in one iteration); `docs/tools/stress_test.md` deleted with the human's OK by name; docs, README and server instructions pruned. The two modules stay for a deletion iteration (B-038). · Failing-first check: `tests/fixture_ground_truth.rs::stress_test_is_absent_or_reports_what_it_did` failed on the old code ("asked for 1 s, the stress test ran 30.121794397s"); it is now `tests/tool_list.rs::stress_test_is_not_offered` (see "Test and eval diffs").

### B-035: `tools/list` returned the tools in a different order on every launch
Must-fix: misleads y, blocks n, common/no workaround n — 4 launches, 4 orders; rmcp 0.2.1's `#[tool_handler]` returns `ToolRouter::list_all()`, a `HashMap`'s values.
Fix: `list_tools` written out and sorted by name. · Failing-first check: `tests/tool_list.rs::tools_are_listed_by_name_and_in_the_same_order_every_launch` (metamorphic: four launches of the real binary) failed with the unsorted list.

### B-036: a missing `bevy_fairy/*` method named no fix, or the wrong one
Must-fix: misleads y, blocks n, common/no workaround y — `screenshot` said a bare "Method `bevy_fairy/screenshot` not found"; `guide` prescribed `--features debugger`, which this crate does not have.
Fix: `server::brp::refusal_text` names `plugin`, `plugin-screenshot` or `plugin-guide` on METHOD_NOT_FOUND. · Failing-first check: `tests/fixture_ground_truth.rs::a_missing_{guide,screenshot}_method_names_the_feature_that_registers_it` (ground truth: the fixture is built without those features) failed on the old text.

### B-037: handler refusals came back as successful results
Must-fix: misleads y, blocks n, common/no workaround y — live pass: `observe` "Query parsing failed" with `isError: false`; the tool contract says failures come back as tool errors.
Fix: `mcp_tools::handler_result` sets `isError` when a handler's body has a non-null top-level `error`, for `observe`, `detect_anomaly`, `hypothesis`, `experiment` and `replay` (`guide`'s refusals were already JSON-RPC errors; B-048). · Failing-first check: `tests/tool_contract.rs::an_unparseable_observe_query_comes_back_as_a_tool_error` and the new `isError` assertion in `an_unknown_action_is_refused_with_the_valid_ones` both failed (`left: Some(false)`).

### B-046: `release.yml` published with no token, and its verify step could not fail
Must-fix: misleads y, blocks y, common/no workaround n — the Publish step ran `cargo publish` with no token, on the claim that cargo mints one from OIDC (it does not; crates.io's docs use `rust-lang/crates-io-auth-action`); "Verify the release" ran `cargo info bevy_fairy@<v>` inside the workspace, which reports the local manifest (`version: 0.2.0 (from ./)`, observed with the crate not on crates.io).
Fix: authenticate with `rust-lang/crates-io-auth-action@v1`; ask the crates.io API whether the version exists (skip if already published, fail the verify if not). · Failing-first check: none runnable here — it is CI configuration; the `cargo info` behaviour was reproduced locally, inside and outside the workspace.

Candidates considered: the eval suite (required by the bootstrapping rule); deleting the stress modules and `--tcp` (B-038, B-012); a watch tool (B-045). The bootstrapping rule decided it.

**Deviation: diff size.** 661 lines (450 runner, 115 task data, 67 README, 29 docs), over the ~400 cap. A runner without tasks, or tasks without a runner, proves nothing, and the runner alone is 450 lines; splitting it would not have produced a provable piece.

**Deviation: Phase 1 budget.** Five must-fix bugs were fixed (four tool, one release), at the "roughly five" budget, and Phase 2 was not skipped, because the bootstrapping rule requires the suite and without it the eval-regression gate cannot run at all. B-039 and B-041 were logged rather than fixed.

**The backend.** The first draft drove the Claude Code CLI, whose separate login had expired. The runner uses `omp -p`, which runs on the same login as the agent running the loop.

## Test and eval diffs
- `tests/tool_contract.rs`: `stress_test_runs_the_requested_test_type` deleted with the tool it tested; `an_unknown_action_is_refused_with_the_valid_ones` now calls `hypothesis` instead of the removed `stress_test`, and gains an `isError` assertion (stronger); `an_unparseable_observe_query_comes_back_as_a_tool_error` added.
- `tests/docs_drift.rs`, `tests/instructions.rs`: `stress_test` dropped from the lists of tools whose docs they check, because the tool is gone.
- `tests/fixture_ground_truth.rs`: two missing-method tests added. The failing-first stress test was moved to `tests/tool_list.rs` as `stress_test_is_not_offered`: its "success" branch assumed spawned entities outlive the run, but the stress test despawns them, so the branch was wrong, and with the tool gone only the absence is checkable. After review (aaf1b00) each missing-method test is compiled out when the feature that registers its method is on: then the fixture serves the method and there is nothing to refuse, so the test would fail for the wrong reason. Under default features both still run.
- `tests/tool_list.rs`: new.
- `evals/`: new this iteration; no task file or fact was changed after a run. After review the runner records omp's own timeouts and exit code, and leaves held-out answers out of `evals.jsonl` (72899c9); the six held-out answers already recorded were blanked, their scores untouched.
